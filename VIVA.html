What is the project?

What did you make?

A website that tells you when to leave on 13 Gurugram roads. You pick a day. The map colours each road for each hour. It shows best time, avoid time, and extra minutes versus an empty road. You can also type two places and see a trip.

Site: gurugram-traffic-predictor.vercel.app

What is the one question it answers?

If I have to drive this road on this weekday, which hour is better?

The number

What is congestion index?

How much of the trip is lost to traffic, from 0 (empty) to 1 (stuck).

index = 1 − (empty time ÷ expected time)

Empty time = TomTom’s no-traffic time. Expected time = travel time with traffic. Extra minutes = empty × index / (1 − index).

Labels: Free below 0.091, Moderate below 0.20, Heavy below 0.31, Severe above that (about 1.10×, 1.25×, 1.45× empty time).

How do you predict?

served value = clip(baseline + residual, 0, 1)

Baseline = TomTom’s typical hour for that weekday (date-blind: every Friday 6pm is the same). Residual = leftover the model learned (rain, jams nearby, what the road did recently). clip keeps it between 0 and 1.

Data

Where does data come from?

TomTom Routing API only. Same API for typical hour and live time. Weather from Open-Meteo (free, no key). Jams from TomTom Incidents, only if within 300 m of the road line. Holidays: Python holidays for Haryana.

Why Routing, not Flow Segment?

This TomTom key is Routing-only. Flow Segment and Search returned 403. So both live and typical times come from Routing: future departAt for the typical week, departAt=now for live.

How much data?

24,490 live rows, 16 Aug to 15 Oct 2026, 61 days. After dropping wrong-length routes and rows with no baseline: 20,198 used to train. Grid is 13 × 7 × 24 = 2,184 slots.

Why drop rows?

If TomTom’s route length is more than 2% off the mapped road, it snapped to the wrong road. Those rows would train the model on a different street.

Model

Which algorithm?

scikit-learn GradientBoostingRegressor. Many small decision trees, each one fixes the last one’s mistakes. It predicts the leftover, not the whole congestion from scratch. Saved as a .joblib file.

Why leftover, not the full number?

Rush hour is already in TomTom’s typical hour. The model only has to explain the extra: a jam, rain, yesterday. If it cannot beat that typical hour on later days, we do not ship it.

What features?

Mainly hour of day (sine and cosine so 23:00 is near 00:00), recent lag, incidents, road class (arterial / expressway / highway). Time of day does most of the work. That matches real life: 8am is busy, 2am is not.

Did you try anything else?

An MLP (neural net) on the same split. It was worse. Not used.

How do you know it works?

Train on earlier days, test on later days (4–15 Oct). Labels match live 77.9% of the time. Ranking two hours correctly 88.1% of the time. 50% ranking would be a coin flip. Then the final model was refit on all 20,198 rows.

Roads

13 corridors. Classes: arterial, expressway, highway.

  • NH-48, MG Road, Golf Course Road, Sohna Road
  • Dwarka Expressway, Golf Course Extension, Mehrauli–Gurgaon Road, SPR
  • KMP, Delhi–Mumbai Expressway, NH-352W, Old Delhi–Gurgaon Road, Pataudi Road

Why 13, not 8?

Eight roads were mostly arterials. Holding out Dwarka or NH-48 left no similar road to learn from. Extra expressways and highways were added so each class has siblings.

Why not use corridor name as a feature?

The model should learn “expressway at 8am”, not memorise “Dwarka”. We use road class, not corridor id.

Site behaviour

Is this live Google Maps?

No. It is a typical week (baseline + residual). Not “NH-48 this second.” Trip planner uses live TomTom for the path; congestion on our 13 roads still uses the typical-week forecast.

What if the model file is missing?

API returns HTTP 503. No made-up table. Tests check that.

Biggest extra time you show?

About 13 minutes, KMP, Monday 8am versus 10pm. A 30-minute jam on one day is not what this typical-week grid is for.

How do I run it?

./run.sh — Flask + a local web server. Do not double-click the HTML; the browser blocks the map data on file://.
